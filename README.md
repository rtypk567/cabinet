# Кабинет самозанятого

Мобильный кабинет на Next.js 15 + TypeScript: закрытый вход (почта и пароль, Telegram или номер телефона), главная с выручкой и налогом, операции, статистика.

**Шаг 1 (готово):** настоящая авторизация. **Шаг 2:** операции, продажи и налог из базы (сейчас демо-данные из `src/lib/demo.ts`).

## Запуск

```bash
npm install
cp .env.example .env.local   # затем заполнить (см. ниже)
npm run dev                  # http://localhost:3000
```

Нужен Node.js 20+.

## Аккаунты

Регистрации на сайте нет: аккаунты создаёте только вы командой в терминале (из папки проекта). Войти могут только те, кого вы добавили.

```bash
npm run user -- add --email me@example.com --password "длинный пароль" --name "Ярослав"
npm run user -- add --email me@example.com --password "..." --name "Ярослав" --phone +48600100200 --telegram-id 123456789
npm run user -- update --id 1 --phone +48600100200      # добавить способ входа существующему
npm run user -- update --id 1 --password "новый пароль"
npm run user -- update --id 1 --telegram-id none        # отвязать
npm run user -- list
```

- Почта и пароль входят вместе. Телефон нужно добавить заранее в формате `+48600100200`, иначе код на него не придёт.
- Telegram привязывается по числовому id (его показывает бот @userinfobot), а не по @username.
- Пароль в команде остаётся в истории терминала. Для боевого сервера поменяйте его после первого входа или очистите историю.
- Команда работает с той же базой, что и сайт (`DATABASE_PATH` из окружения или `.env.local`, иначе `./data/app.db`). Сервер при этом можно не останавливать.

### Переменные окружения (`.env.local`)

| Переменная | Что это |
| --- | --- |
| `SESSION_SECRET` | Секрет подписи сессий, от 32 символов: `openssl rand -base64 48`. В production без него приложение не стартует. |
| `TELEGRAM_BOT_TOKEN` | Токен бота от @BotFather. Нужен только на сервере (проверка подписи входа и определение имени бота), в браузер не попадает. Без него кнопка Telegram скрыта. |
| `TELEGRAM_BOT_USERNAME` | Необязательно: имя бота вручную. По умолчанию сервер узнаёт его у Telegram сам. |
| `DATABASE_PATH` | Файл SQLite, по умолчанию `./data/app.db`. |
| `NEXT_PUBLIC_LOGO_SRC` | Путь к вашему логотипу, например `/logo.svg`. |
| `COOKIE_SECURE` | `false` только для проверки `npm start` по `http://localhost`. |
| `PHONE_PROVIDER` | Канал доставки кода. Сейчас только `console` (по умолчанию в dev), см. раздел про номер. |

## Вход через Telegram

1. В @BotFather: `/newbot`, получите токен и username.
2. `/setdomain` → выберите бота → укажите домен, где будет работать сайт.
3. Впишите токен в `.env.local` одной строкой: `TELEGRAM_BOT_TOKEN=123456789:AA...` и перезапустите `npm run dev`. Имя бота определится само.

Виджет Telegram работает только на https и только на домене из `/setdomain`. На `localhost` он не откроется. Для проверки с компьютера поднимите туннель (например, `cloudflared tunnel --url http://localhost:3000`) и укажите его домен в `/setdomain`.

Сервер проверяет подпись данных (HMAC-SHA256 по токену бота) и отклоняет данные старше 24 часов. Войти может только Telegram-аккаунт, чей id добавлен командой выше; остальным сервер отвечает 403.

## Вход по номеру телефона

Человек вводит номер сам (в формате `+380501234567`, пробелы и скобки допустимы), получает 6-значный код и вводит его на сайте. Номер должен быть заранее добавлен вам командой `npm run user`. Для неизвестных номеров ответ сайта точно такой же, как для известных (код просто не отправляется), чтобы нельзя было выяснить, кто подключён. В dev-режиме сервер печатает подсказку, что номер не добавлен.

**Сейчас работает тестовый режим:** код не отправляется, а печатается в окне терминала, где запущен `npm run dev` (`[phone-auth] код для +380…: 123456`). На странице никаких подсказок нет. В production (`npm run build` + `npm start`) вкладка «Телефон» скрыта, пока вы не подключите реальный канал.

Подключение реального канала: в `src/lib/sms.ts` в функции `getCodeSender()` добавьте ветку (Telegram Gateway или SMS-провайдер) и задайте `PHONE_PROVIDER`. Эндпоинты и экран менять не нужно. [Telegram Gateway](https://core.telegram.org/gateway/api) шлёт код в Telegram по номеру (метод `sendVerificationMessage`, токен доступа из кабинета gateway.telegram.org), работает только для номеров с Telegram и платный за доставленные коды.

Правила: код действует 5 минут, одноразовый, 5 попыток на код, повторная отправка не чаще раза в минуту, до 5 кодов в час на номер и 10 запросов в час с одного IP. В базе хранится не код, а его HMAC с секретом `SESSION_SECRET`.

## Свой логотип

Положите файл в `public/` (например, `public/logo.svg`) и задайте `NEXT_PUBLIC_LOGO_SRC=/logo.svg`. Пока переменная пуста, на экране входа показана пунктирная заглушка. Название сервиса меняется в `src/app/login/page.tsx` и `src/app/layout.tsx`.

Используйте собственные название и эмблему. Не размещайте на экране входа символику государственных органов: страница, похожая на официальный портал, вводит людей в заблуждение.

## Как устроена авторизация

- `POST /api/auth/login`, `/telegram`, `/logout`, `/phone/send`, `/phone/verify`. Эндпоинта регистрации нет.
- Пароли хэшируются scrypt (встроен в Node), параметры хранятся вместе с хэшем.
- Сессия: подписанный токен HS256 в cookie `httpOnly`, `SameSite=Lax`, `Secure` в production, 30 дней.
- `src/middleware.ts` перенаправляет неавторизованных на `/login`; страницы дополнительно проверяют пользователя в базе.
- Защита: проверка `Origin`, ограничение частоты попыток, одинаковый ответ для неверной почты и неверного пароля.
- База: SQLite через `better-sqlite3`, таблица создаётся автоматически. Весь доступ к базе в `src/lib/db.ts`.

## Что пока не сделано

- Реальная доставка кода на номер (пока только тестовый режим), сброс пароля.
- Смена имени и аватарки из интерфейса (сейчас имя задаёт `npm run user -- update --name`, аватарка подтягивается из Telegram).
- Ограничение частоты хранится в памяти процесса: при нескольких серверах нужен общий склад (Redis/Upstash).
- SQLite-файл не сохраняется на serverless-хостингах вроде Vercel. Для них замените `src/lib/db.ts` на Postgres/Turso, остальной код не меняется. На VPS или Docker с томом SQLite подходит как есть.
- Кнопки «Новая продажа» и «Оплатить» пока без действий.

```
src/app/api/auth         эндпоинты авторизации
scripts/users.mjs        создание и правка аккаунтов (npm run user)
src/components           LoginForm, PhoneLogin, TelegramLogin, TabBar, Logo, LogoutButton
src/lib                  db, jwt, session, password, telegram, phone, sms, http, demo
src/middleware.ts        защита маршрутов
```
